Headline

Where we are aligned

  • Execution architecture. Waveless, pull-based release matches the direction of Manhattan Order Streaming, Blue Yonder pull-based WES and SSI Schäfer waveless.
  • Integration contract. CloudEvents 1.0, AsyncAPI, OpenAPI and an MCP server on every context.
  • Explainability and governance. Fail-closed transfer proposals with reason codes; a zero-write, allowlisted agent.
  • Transparent observability. Correlated metrics, traces and logs that can be inspected end to end.

Where we trail

  • Optimisation and ML. Forecasting, slotting and task-time prediction are deterministic or absent; leaders market ML as the differentiator.
  • Automation edge. No WCS, robotics or AMR orchestration yet (a seam is reserved).
  • Breadth. No returns, lot/serial/expiry tracking, ERP connectors or mobile operator UX.
  • Production readiness. No identity, alerting/SLOs or persistent telemetry; deliberate for the study scope, blocking for real use.

Reading this page. The fleet is an educational DDD study project, not production software. Ratings compare it against vendor-published capabilities of mature commercial suites; a "gap" means the capability is not evidenced in the repository docs reviewed, not that the project is deficient for its purpose.

Domain detail

Inventory & Storage

Partialinventory-storage

Leader benchmark. Bin-level real-time visibility reconciled with ERP; lot/batch, serial and expiry (FEFO/FIFO) traceability; directed putaway by size and access frequency; 99.9%+ accuracy positioning.

Leaders: Manhattan, Blue Yonder, SAP EWM, Körber, SSI Schäfer
Edge: Item-scan + location-scan invariant and revocable reservations give bin-accurate, auditable stock.

What we have

  • Chaotic-storage stow with item-scan + location-scan invariant and bin-capacity enforcement
  • Revocable reservations with allocations naming the pick bin
  • Cycle counting that marks shortfalls Unlocated and emits DiscrepancyDetected
  • DOT hazard-class matrix for hazmat/temperature placement

Gaps vs leaders

  • HighNo lot/batch, serial or expiry (FEFO) traceability in the documented model
  • MediumNo directed putaway: leaders assign bins by size and access frequency
  • MediumCycle-count overage reconciliation deferred to a separate, unbuilt process
  • MediumNo ERP/physical-inventory reconciliation connector

Closing the gap

Next  Add lot / serial / expiry attributes and FEFO draw to ReserveStock (new ADR)
Later  Directed-putaway policy fed by facility-layout travel geometry

Order Management

Partialorder-management

Leader benchmark. Orders, inventory and promising as one solution; future inventory in promising; geo-proximity sourcing across nodes; returns with disposition decisioning; digital self-service.

Leaders: Manhattan (ActiveOrder / Active Omni), Blue Yonder, Körber
Edge: Fail-closed allocation saga and capability-derived promising grounded in real path cycle times.

What we have

  • Allocation-then-release saga with fail-closed semantics
  • Capability-derived CPT-window promising with lead-time fallback
  • Attribute-driven multi-path routing by shortest eligible cycle time
  • Cancellation up to the release boundary with reservation revocation

Gaps vs leaders

  • HighNo returns / reverse-logistics flow
  • MediumRelease is fire-and-forget: no confirmation from wes-work-planning (ADR 0005 deferral)
  • MediumNo multi-node sourcing by proximity or cost; promising ignores future inventory
  • MediumKnown sweeper gaps: orphaned holds and released-work claw-back can leave reservations lingering
  • LowNo customer self-service (cancel, track, return)

Closing the gap

Now  Ship release-confirmation reply events (ADR 0005 follow-up)
Now  Expiry sweeper for held orders (ADR 0020 known gap)
Later  Scope a Returns bounded context with its own ubiquitous language

Labor & Workforce

Partiallabor-performance, workforce-management

Leader benchmark. Engineered time standards feeding incentive pay; ML resource forecasting by role/task/zone days ahead; real-time mid-shift rebalancing; capture of direct, indirect and lost-time labor.

Leaders: Manhattan (Active Labor), Blue Yonder, Körber
Edge: Certification-gated assignment is enforced by construction; standards are append-only and replayable.

What we have

  • Append-only engineered LaborStandards per task type, scored against the standard active at completion
  • Certification-gated assignment; double-booking impossible by construction
  • Headcount proposal heads = ceil(charge / measured rate) with human commit
  • Per-associate scorecards, coaching flags and idle/utilization derivation

Gaps vs leaders

  • HighForecasting is a deterministic formula; no ML demand-to-labor forecast
  • MediumRebalancing is advisory; drift (PathPlanDriftDetected) does not trigger action
  • MediumPay-for-performance, gamification and automated coaching are out of scope
  • MediumNo indirect/lost-time activity capture or task interleaving
  • LowStaffing gap is derived from recorded assignments, not physical presence

Closing the gap

Next  Forecast model behind a port, fed by labor-performance measured rates
Next  Close the drift loop: RebalanceDecision acts on PathPlanDriftDetected

Facility Layout & Slotting

Gapfacility-layout

Leader benchmark. Continuous ML-driven slotting producing daily slot plans; explainable recommendations from demand, travel path and space; robot-native dynamic slotting; 3D warehouse modeling.

Leaders: Blue Yonder (Advanced Slotting), Manhattan, SAP EWM, Geek+, Körber
Edge: Travel graph and placement-rule legality already provide the geometry a slotting engine needs.

What we have

  • System of record for Site-Area-Zone-Aisle-Bay-Level-Position hierarchy
  • Placement-rule legality (Deny/Allow by zone predicate)
  • Metre-weighted travel graph with shortest-path /distance and SVG floor plan
  • Bulk layout import with atomic-per-row partial success

Gaps vs leaders

  • HighNo slotting engine: re-slotting is declared rare, whereas every leader sells it as a core optimizer
  • MediumCross-zone distance is a straight-line estimate unless both slots carry geometry
  • LowHierarchical codes change when the building is reorganised (accepted trade-off)
  • LowUnderMaintenance state exists but no use case sets it; decommission is one-way

Closing the gap

Next  Slotting decision-support context consuming facility-layout geometry, inventory velocity and order demand (own ADR; keeps facility-layout write-side clean)

Execution (WES) & Automation

Partialwes-work-planning, fulfillment-execution, process-path-management

Leader benchmark. Waveless, continuously re-prioritised release; pull-based WES with ML-predicted task durations; native robotics/AS-RS/conveyor orchestration (Geek+ up to 5,000 robots; LocusONE 1,000+ AMRs).

Leaders: Manhattan (Order Streaming), Blue Yonder (embedded WES), SSI Schäfer, Geek+, Locus
Edge: Waveless, pull-based release is the same design direction as Manhattan Order Streaming, Blue Yonder pull-based WES and SSI waveless.

What we have

  • Waveless CPT-ordered release bounded by per-pool WIP limit (architecturally aligned with Manhattan/Blue Yonder/SSI)
  • Pull-based dispatch: station claims best-fit task under a time-boxed lease
  • Flow balancing as a domain service from live backlog telemetry
  • Operator-configurable process-path catalogue and CPT schedule as published language

Gaps vs leaders

  • HighWCS / equipment edge not wired; only an anti-corruption seam is reserved (fulfillment ADR-0015)
  • HighNo robotics / AMR / AS-RS orchestration or vendor-agnostic automation hub
  • MediumSingle-dimensional CPT priority; customer tiering or cold-chain needs a ReleasePolicy change (ADR 0002)
  • MediumCycle times are declared (cycleTimeP95), not predicted by ML
  • MediumPermissive no-op defaults omit hazmat/travel hints on WorkReleased until http lookups are enabled
  • LowPublished fields (destination_location_role, eligibility) decoded by few or no consumers

Closing the gap

Now  Promote PRODUCT_CLASSIFICATION_MODE / TRAVEL_DISTANCE_MODE from permissive to enforced lookups
Next  Implement the WCS anti-corruption adapter reserved in fulfillment ADR-0015
Later  Task-duration prediction behind a port, validated against labor-performance actuals

Network & Capacity Planning

Gapnetwork-inventory-planning, network-fulfillment, warehouse-planning

Leader benchmark. Multi-echelon inventory optimisation with dynamic safety stock; constraint-aware allocation and DC-to-DC rebalancing; scenario planning before commit; optimised parameters feed execution.

Leaders: Blue Yonder (multi-echelon planning), Manhattan (future inventory)
Edge: Explainable, fail-closed proposals (score breakdown, policy version, reason codes) are auditable by design.

What we have

  • Deterministic, explainable transfer proposals (score breakdown, policy version, reason codes) that fail closed on stale data
  • Transfer saga with allocation replies driving ALLOCATED / UNFULFILLABLE
  • Anti-corruption layer and capability offers toward an external retail network
  • Effective-capacity and bottleneck detection per process path with shortage detection

Gaps vs leaders

  • HighNo demand forecasting, MEIO or dynamic safety stock: planning is deterministic rules only
  • HighTransfer lifecycle after ALLOCATED (dispatch, receipt, reconciliation, revocation) still being built; single-line transfers only
  • HighRetail-network adapter is stub-only; NETWORK_MODE=live refuses to boot
  • MediumNo what-if / scenario planning before committing a plan
  • MediumStation standards are operator-declared because no upstream publishes per-station throughput

Closing the gap

Now  Finish transfer lifecycle: dispatch, receipt/stow with transferId, TransferArrived consumption
Next  Build the live retail-network HTTP adapter behind the existing port
Later  Forecasting port for demand and safety stock; keep deterministic policy as fail-closed fallback

Leaders: Manhattan, Blue Yonder, Körber (HTML5), SAP (Fiori), SSI Schäfer (3D)

Agentic Operations (AI)

Partialwarehouse-ops-agent

Leader benchmark. AI agents sharing the WMS data model and audit logs; conversational briefings, exception explanations and next-best-action; governed autonomous actions through the same APIs.

Leaders: Manhattan (Wave Coordinator, Labor, Associate agents; Agent Foundry), Blue Yonder (Warehouse Ops Agent)
Edge: Governance-first posture: zero-write, allowlisted tools and deterministic fallback.

What we have

  • Read-only decision support across nine contexts via MCP with zero write capability
  • Daily brief, flow-balance advisory and stranded-reservation detection with blast radius
  • LLM reasoner in off/shadow/on modes with 8 s timeout and deterministic fallback
  • Per-path graceful degradation when an upstream is unavailable

Gaps vs leaders

  • HighNo governed write path: autonomous action needs an authorization gate plus human confirmation first
  • MediumLLM reasoner covers flow-balance only; DailyBrief not yet; shadow mode doubles inference cost
  • MediumTwo MCP clients (order-management, process-path-management) wired but unconsumed
  • LowNo conversational interface or agent builder comparable to Agent Foundry

Closing the gap

Now  Consume the wired-but-unused order-management and process-path MCP clients
Next  Extend the LLM reasoner to DailyBrief after reviewing shadow agreement metrics
Next  Design the authorization + human-confirmation gate before any write slice

Platform, Observability & Delivery

Partialwarehouse-infra, warehouse-harness-template, e2e-tests

Leader benchmark. Zero-downtime continuous delivery; 99.9% uptime with auto-scaling and multi-AZ failover; operational KPI telemetry as a product surface. Note: vendor SRE claims are self-reported; independent SLO/MTTR benchmarks are scarce.

Leaders: Blue Yonder, Manhattan (zero-downtime CD, multi-AZ failover), SSI Schäfer (KPI telemetry)
Edge: Open, correlated telemetry (exemplars to traces to logs) is fully inspectable; vendor SRE claims are self-reported.

What we have

  • Open, correlated telemetry: OTel Collector, Jaeger, Prometheus, Grafana, Loki + Alloy, Kiali, Kong metrics
  • Metric exemplars link to traces; log lines link to traces (two-way navigation)
  • Generated per-context Grafana dashboards: edge RED, business counters, Go runtime, logs
  • Harness engineering: mutation gates, architecture fitness tests, black-box e2e and soak

Gaps vs leaders

  • HighNo alerting: Alertmanager disabled; no SLOs or error budgets
  • HighTelemetry is ephemeral: Jaeger in-memory, Prometheus 24 h emptyDir, Loki no persistence
  • HighLocal kind cluster: no HA, multi-AZ failover or zero-downtime rollout evidence
  • Medium/healthz does not check the database
  • LowMutation gate on order-management pinned below the fleet 99/99 standard

Closing the gap

Now  Enable Alertmanager with SLO burn-rate alerts per context
Now  Real readiness probes (database-aware /healthz)
Next  Persist traces, metrics and logs (PVC or object storage) before any non-local use

Integration, Events & Security

Partialwarehouse-docs

Leader benchmark. API-first composable services; vendor-agnostic robotics connectivity; prebuilt ERP connectors (SAP, Oracle, Dynamics, NetSuite); webhooks; enterprise identity.

Leaders: Manhattan (API-first microservices), Blue Yonder (Robotics Hub), Geek+ (REST + webhooks), SAP EWM (ALE/qRFC)
Edge: One uniform event contract (CloudEvents 1.0 + AsyncAPI) and an MCP server on every context.

What we have

  • CloudEvents 1.0 mandatory on every Kafka message with published AsyncAPI per context
  • Spectral-linted OpenAPI plus an MCP server per context (agent-ready by design)
  • Transactional outbox, idempotency keys, processed-events dedup
  • Published-language contexts (process paths, CPT) with zero outbound dependencies

Gaps vs leaders

  • HighEvery REST and MCP endpoint is unauthenticated; no identity, RBAC or multi-tenancy. Deliberate decision for the study scope, a hard blocker for any real deployment
  • HighNo prebuilt ERP connectors (SAP, Oracle, Dynamics) or partner webhooks
  • MediumNo vendor-agnostic robotics/automation connectivity layer
  • LowOutbox and idempotency only active when DATABASE_URL is set; in-memory mode skips them

Closing the gap

Now  Decide the identity model (OIDC, per-context scopes) before leaving study scope: a user decision, not assumed
Later  ERP connector as an anti-corruption adapter, following the network-fulfillment pattern
