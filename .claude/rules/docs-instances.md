# The network, storefront and yard docs instances

Moved verbatim from this repo's CLAUDE.md (now a short map). Paths in another repo are written
as words, not backticked: guide-lint resolves every backticked path in THIS repo.

The site has four docs instances: the WMS/WES fleet at `/`, the
**retail-network** domain at `/network/` (second
`@docusaurus/plugin-content-docs` instance, id `network`, sidebar
`network-sidebars.ts`, OpenAPI plugin instance `network-api`). The `network/`
tree merged in from `IQVO/retail-network-docs` with full history; its source
of truth is `network/model/model.yaml`, and the model-derived strategic pages
under `network/docs/strategic-design/` are generated by
`network/scripts/gen_pages.py` (gates `npm run check:model:network`,
`npm run check:pages:network`). The network REST reference is generated at
build time and gitignored, unlike the committed fleet reference.

The third docs instance is the **digital storefront** at `/storefront/`
(plugin id `storefront`, sidebar `storefront-sidebars.ts`, OpenAPI plugin
instance `storefront-api` with seven entries: the six contexts plus
`storefrontBff`). Same shape as the network section: source of truth
`storefront/model/model.yaml`, generated pages under
`storefront/docs/strategic-design/` from `storefront/scripts/gen_pages.py`
(gates `npm run check:model:storefront`, `npm run check:pages:storefront`),
hand-written 14-page context packs, `storefront/apis/<repo>/openapi.yaml`
copies of each service's spec (Spectral-linted in CI), REST reference
generated at build time and gitignored. Status (2026-10-27): all six context
services (`pricing`, `product-content`, `product-discovery`, `shopping-cart`,
`checkout`, `customer-payments`) plus `storefront-bff`, `storefront-web` and
`payment-provider-simulator` are built on `develop` and NOT deployed (no
warehouse-infra terraform/apps.yaml entry): write "built on develop, not
deployed", never "running". The ADR index `storefront/docs/adr/index.md` links
out to all nine repos' ADRs.

The fourth docs instance is the **yard** at `/yard/` (plugin id `yard`, path
`yard/docs`, sidebar `yard-sidebars.ts`): two WMS-tier contexts,
`dock-scheduling` (the door calendar) and `yard-management` (the physical
yard), with `com.warehouse.wms.<ctx>` event types. Source of truth is
`yard/model/model.yaml`; the strategic pages under `yard/docs/strategic-design/`
are generated by `yard/scripts/gen_pages.py` (gates `npm run check:model:yard`,
`npm run check:pages:yard`) and the 14-page context packs are written here
from the model. Both services are built on `develop` (merged 2026-11-08) and
registered in warehouse-infra `develop` (terraform/apps.yaml entries, helm
values, dashboards and alert rules, images pinned at v0.1.1; PR 193) but NOT
applied to the cluster (no pods): write "built on develop, registered in
warehouse-infra, not applied", never "running" and never "proposed, not
built". Check `kubectl get pods -n warehouse-systems` before changing it.
