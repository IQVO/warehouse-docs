outbound-shipping Domain Events 1.0.0
  • UNLICENSED
  • application/json
  • outbound-shipping maintainers
  • outbound-shipping@iqvo.example.com

Event contract for the outbound-shipping bounded context (WMS subdomain): staging, the outbound load, ship-confirm on the trailer's physical departure, and the bill of lading (ADR 0001, ADR 0002, ADR 0005).

Published. Three aggregates raise thirteen events, published to warehouse.outbound-shipping.events through a transactional outbox: the aggregate row and its already-encoded events are written in ONE database transaction and a relay drains them to Kafka (at-least-once; the CloudEvents id is stored with the outbox row, so a retry republishes the same id). Every payload carries the aggregate version AFTER the change, so consumers can reject out-of-order deliveries.

Analytics. Every published event is ALSO written, in the same transaction and under the same id, to warehouse.outbound-shipping.analytics with dataschema urn:warehouse:outbound-shipping:analytics:<EventName>:v1. That stream is not an integration contract: only this service's own projector consumes it. Other contexts keep reading warehouse.outbound-shipping.events.

Consumed (ADR 0003, ADR 0005). PackageManifested and PackageDiverted from fulfillment-execution; CPTScheduleChanged from process-path-management; ZoneRegistered and LocationSlotRegistered from facility-layout; DockAppointmentBooked from dock-scheduling (pinned from its origin/feature/service until that contract merges); TrailerDocked, DoorWorkCompleted and TrailerDeparted from yard-management (pinned to its merged contract, contracts/yard-management.asyncapi.yaml, ADR 0010 there). Each feeds a durable local copy. The consumed messages below are the producers' own contracts, decoded independently here and never imported.

Envelope (mandatory). CloudEvents 1.0, structured content mode, Kafka header content-type: application/cloudevents+json; charset=UTF-8. type = com.warehouse.wms.outbound-shipping.<entity>.<EventName> where <entity> is the raising aggregate lowercase with no separators: outboundload, shippingpackage, billoflading. Kafka key = aggregate id. Dispatch on the full type, ignore unknown types, dedupe on id.

Operations

  • SUB warehouse.outbound-shipping.events

    This service's integration topic. Written by the outbox relay; key = aggregate id, so all events of one load (or package, or BOL) stay ordered on one partition. Every message carries the CloudEvents content-type header. Dispatch on the full type, ignore unknown types, dedupe on id.

    Receive outbound-shipping events.

    Subscribe to the outbound shipping facts. Route on the full type (com.warehouse.wms.outbound-shipping.<entity>.<EventName>). ShipmentConfirmed is the fleet's "this actually shipped" fact (ADR 0002, ADR 0004); PackageMissedLoad drives exception cases and re-promising.
