Event catalog for the inbound-receiving bounded context (WMS subdomain): the inbound dock workflow of ASNs, dock appointments and receipts (ADR 0001, ADR 0002).

Published. The Asn and Receipt aggregates raise eight events, published to warehouse.inbound-receiving.events through a transactional outbox: the aggregate row and its already-encoded events are written in ONE database transaction and a relay drains them to Kafka (at-least-once; the CloudEvents id is stored with the outbox row, so a retry republishes the same id). Consumers dedupe on id. The four dockappointment types (Booked, CheckedIn, Cancelled, Completed) are RETIRED: the DockAppointment moved to dock-scheduling (ADR 0019, plan YD-0002), the backfill command that republished them is gone and this service raises none (ADR 0022), so they are no longer declared. Read dock-scheduling's events instead. ReceiptLineReceived is the handover event: inventory-storage consumes it and books condition=Good quantities into stock (ADR 0003); Damaged quantities are recorded here and not booked.

Consumed (ADR 0003). ProductRegistered from warehouse.product-master.events feeds the known_skus local copy (group from env PRODUCT_CONSUMER_GROUP); ProductPackLevelDeclared and ProductPackLevelRetired from the same topic feed the packaging view (group from env PACKAGING_CONSUMER_GROUP). LocationSlotRegistered and LocationSlotDecommissioned from warehouse.facility.events feed the dock_doors local copy (group from env DOCK_DOOR_CONSUMER_GROUP). The three consumers always run: PRODUCT_MODE / DOCK_DOOR_MODE accept only kafka (or unset) and permissive / off are boot errors, as is an unset group variable. DockAppointmentBooked and DockAppointmentCancelled from warehouse.dock-scheduling.events feed the appointments local copy (group from env DOCK_APPOINTMENT_CONSUMER_GROUP, ADR 0019), and DockAppointmentRescheduled / DockAppointmentDoorReassigned keep its door and window current (ADR 0020): inbound appointments only, guarded by dock-scheduling's version; applying them publishes nothing. Receipts validate their appointment against that copy and take its door when they open; an open receipt keeps its door.

Analytics (ADR 0006). The eleven events are ALSO written, in the same transaction, to warehouse.inbound-receiving.analytics with the same type and the same id per occurrence, dataschema urn:warehouse:inbound-receiving:analytics:<EventName>:v1 and payloads equal to the integration payloads. Only this service's inbound-projector consumes it; it is not an integration contract. The retired dockappointment events already on that stream stay projected (ADR 0022).

Planned. warehouse-planning reads appointments from dock-scheduling (companion of plan YD-0002).

Envelope (mandatory). CloudEvents 1.0, structured content mode, Kafka header content-type: application/cloudevents+json; charset=UTF-8. Optional W3C trace-context headers (traceparent, and tracestate / baggage when present) carry the trace of the request that wrote the outbox row (ADR 0009); consumers may extract them, and must not require them. specversion, id, source (/warehouse/inbound-receiving), type, subject (the aggregate instance id), time, datacontenttype (application/json) and dataschema (urn:warehouse:inbound-receiving:events:<EventName>:v1) are all required. type = com.warehouse.wms.inbound-receiving.<entity>.<EventName> with <entity> one of asn, receipt. Kafka key: asn_number for asn.* and receipt.*. data is snake_case, optional fields are omitted when unset, timestamps are RFC 3339 UTC. A breaking payload change is a new .v2 type, never a mutation.

    • #9Receiving advice issued

      What was received and accepted per line, with W13/CBV-coded discrepancies, for the supplier or the 3PL depositor (ADR 0023).

      • application/cloudevents+json

      type = com.warehouse.wms.inbound-receiving.receipt.ReceivingAdviceIssued; subject = the receipt id, key = the ASN number. The domain fact only: this service renders no EANCOM, X12 or transport. Raised exactly once per receipt, in the same transaction as ReceiptClosed (right after it), for a receipt closed after this event existed; a receipt closed earlier gets no advice. despatch_advice_ref is the ASN number (the reference to the despatch advice), supplier_ref the supplier as the ASN knows it and owner_ref the 3PL depositor (omitted for fleet-owned stock). last_carton_at is when the last unit was received (the receipt's opening when nothing was); within_sla is issued_at - last_carton_at <= sla_seconds (RECEIVING_ADVICE_SLA, default 24 h). Per line the three quantities are exclusive: accepted_qty is the Good units not held, rejected_qty the Damaged ones and held_qty the Good units declared held; received_qty is their sum. discrepancies carry the line kinds Short, Over, Damaged, IncorrectProduct and Hold with w13_code and cbv_disposition. The payload is bounded because a message the broker refuses blocks the outbox (ADR 0007): at most 1000 lines (lines with exceptions first, then in line order; lines_total is the real count and lines_truncated is true when some are left out), at most 1000 SSCCs per line (sscc_count is the real count, ssccs_truncated is true when listed ones are fewer) and at most 200 carton findings (carton_findings_total). A consumer that needs the full list reads the receipt over REST.
